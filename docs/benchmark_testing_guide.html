Benchmark Adapter Testing Guide

How to use DriftBench to generate data and queries for each supported benchmark. Run snippets from the repo root. Artifacts land in ./test_artifacts/.

Related docs: README and quickstart, complete adapter reference, and target orchestration contract. 

from pathlib import Path
import json
OUT = Path("./test_artifacts")

Automated Test Suite

pip install -e ".[test]"
python -m unittest discover -s test -p 'test_*.py' -v
Expected result All discovered tests pass  ·  OK (the exact count grows with coverage)

The five real PostgreSQL 16 integration tests are discovered but skip by default whenever DRIFTBENCH_REQUIRE_PG_INTEGRATION is not exactly 1. The remote Benchmark Regression workflow explicitly sets it to 1 and runs those tests against PostgreSQL 16 with no mocks or skips.

1. TPC-H

Scale factor: sf=1 ≈ 1 GB, sf=10 ≈ 10 GB, sf=1000 ≈ 1 TB.

ModeDescription
mode="generate"Runs dbgen locally. Auto-downloaded & built on first use, cached at ~/.driftbench/cache/tpch-dbgen/.
mode="copy"Copies .tbl files you already have from source_dir.

Data — generate mode

from driftbench.data.tpch import data as tpch_data

result = tpch_data(scale_factor=1, mode="generate").generate(output_dir=OUT)
print("files:", [f.name for f in result.files])

Console output (first run — auto-builds dbgen):

[driftbench] dbgen ready at ~/.driftbench/cache/tpch-dbgen/dbgen

[driftbench] Running dbgen -s 1 in .../tpch/data/sf_1/tables
[driftbench] dbgen complete — 8 tables in .../tables

Output layout:

test_artifacts/tpch/data/sf_1/tables/
  customer.tbl   lineitem.tbl   nation.tbl   orders.tbl
  part.tbl      partsupp.tbl   region.tbl   supplier.tbl

Custom dbgen path:

result = tpch_data(scale_factor=1, mode="generate",
                   dbgen_path="/path/to/dbgen").generate(output_dir=OUT)

Data — copy mode

from pathlib import Path

source = Path("/path/to/existing/tpch/sf1")   # directory with *.tbl files
result = tpch_data(scale_factor=1, source_dir=source).generate(output_dir=OUT)

Convert .tbl → .csv

The .tbl format is pipe-delimited with a trailing | and no header row. Call .as_csv() to get standard CSV (both formats are kept on disk): 

result     = tpch_data(scale_factor=1, mode="generate").generate(output_dir=OUT)
csv_result = result.as_csv()
# result.files     → [customer.tbl, lineitem.tbl, ...]
# csv_result.files → [customer.csv, lineitem.csv, ...]

Queries — qgen mode

from driftbench.data.tpch import queries as tpch_queries

result = tpch_queries(query_ids=[1, 6, 14], queries_per_template=2, mode="qgen").generate(output_dir=OUT)

Output files (2):

  • tpch/queries/tpch_queries.sql — parameterized SQL, one block per instance
  • tpch/queries/tpch_queries.csv — one row per instance: query_id, index, sql
# Verify manifest
manifest = json.loads((OUT / "tpch/queries/tpch_queries_manifest.json").read_text())
assert manifest["count"] == 6           # 3 query IDs × 2 instances
assert manifest["queries_per_template"] == 2
assert manifest["query_ids"] == ["1", "6", "14"]
print("TPC-H queries OK")
Verified reuse Running the same adapter twice reuses existing files only when the normalized parameters and managed-file digests still match: [driftbench] TPC-H queries already exist at … Reusing.

Same as TPC-C plus Zipf-distributed warehouse access weights. Models hotspot workloads.

Extra file (beyond TPC-C):

  • tpcc_skew/data/warehouse_access_weights.csv — columns: warehouse_id, access_probability, is_hot
weights_file = OUT / "tpcc_skew/data/warehouse_access_weights.csv"
lines = weights_file.read_text().splitlines()
assert lines[0] == "warehouse_id,access_probability,is_hot"
assert len(lines) == 6            # header + 5 warehouses
hot = [l for l in lines[1:] if l.endswith(",1")]

Real PostgreSQL regression gate

Adapter generation alone does not measure a database. The release gate runs the generated select_only script and PostgreSQL 16's native -b select-only workload in three alternating AB/BA/AB rounds. Each side receives its own 3-second warmup followed by a 5-second measurement. Before the first run, start PostgreSQL 16 and configure a role that can create and initialize the test database; the pgbench client must also be major version 16. 

pgbench --version
createdb --host localhost --port 5432 --username driftbench driftbench_ci
pgbench --initialize --scale=1 \
  --host localhost --port 5432 --username driftbench driftbench_ci

driftbench benchmark pgbench \
  --policy driftbench/benchmarking/policies/pgbench_ci_v1.json \
  --candidate-script test_artifacts/pgbench_ro/pgbench/queries/pgbench_select_only.sql \
  --output-dir benchmark-artifacts/results \
  --database driftbench_ci --host localhost --port 5432 --username driftbench \
  --json

The output directory must be new or empty. Successful runs retain baseline.json, candidate.json, decision.json, execution_order.json, stdout/stderr, and per-transaction logs. Exit codes are 0 (pass), 3 (configuration), 4 (execution/parser), and 5 (threshold regression). TPS, mean/p50/p95/p99 latency, typed failures, versions, configuration, hashes, and raw paths are all preserved for recomputation. 

driftbench benchmark verify --bundle benchmark-artifacts/results --json

This offline command verifies a persisted or moved bundle without PostgreSQL, network access, or Git. Invalid evidence exits 4 with verified: false and verification_error; a complete verified policy breach exits 5 with verified: true and threshold_failed. See the target contract for complete JSON examples and the distinction from target orchestration outcomes.

Shared Behaviors

Parameter- and content-aware reuse (all adapters)

Every adapter reuses a manifest only when its schema, generator identity, normalized parameters, fingerprint, and each managed file's path, byte count, and SHA-256 all match. A parameter change, content modification, legacy/corrupt manifest, missing file, or path outside the output root is a cache miss and regenerates the artifacts: 

r1 = tpcc_data(scale_factor=1).generate(output_dir=OUT)
original = r1.files[0].read_bytes()

r_same = tpcc_data(scale_factor=1).generate(output_dir=OUT)
# [driftbench] TPC-C data (W=1) already exists at ... Reusing.
assert r_same.files[0].read_bytes() == original

r1.files[0].write_bytes(b"MODIFIED")
r_repaired = tpcc_data(scale_factor=1).generate(output_dir=OUT)
assert r_repaired.files[0].read_bytes() == original   # digest mismatch rebuilt

r_changed = tpcc_data(scale_factor=2).generate(output_dir=OUT)
assert json.loads(r_changed.metadata.read_text())["cache"]["parameters"]["scale_factor"] == 2

r_changed.files[0].write_bytes(b"MODIFIED")
r3 = tpcc_data(scale_factor=1).generate(output_dir=OUT, force=True)
# [driftbench] Generating TPC-C data (W=1) → ...
assert r3.files[0].read_bytes() != b"MODIFIED"   # unconditional rebuild
print("Verified reuse + force=True OK")

BenchBase passwords and JDBC URLs still participate in the fingerprint but appear as <redacted> in manifests. Generated XML necessarily contains the live connection values, so protect the artifact directory as credential-bearing output.

Default output directory

When output_dir is omitted, artifacts go to ~/.driftbench/data/ (or $DRIFTBENCH_DATA_DIR):

import os
os.environ["DRIFTBENCH_DATA_DIR"] = "/tmp/my_driftbench"

from driftbench.data.ycsb import data as ycsb_data
result = ycsb_data().generate()   # no output_dir
print("wrote to:", result.output_dir)
# [driftbench] No output_dir specified. Writing ycsb/data to: /tmp/my_driftbench

.as_csv() for pipe-delimited formats

TPC-H (.tbl) and TPC-DS (.dat) files are pipe-delimited with no header and a trailing |. Call .as_csv() to get standard CSV. Both the original and the new CSV are kept on disk. 

# TPC-H
result     = tpch_data(scale_factor=1, mode="generate").generate(output_dir=OUT)
csv_result = result.as_csv()
# result.files     → [customer.tbl, lineitem.tbl, ...]
# csv_result.files → [customer.csv, lineitem.csv, ...]

# TPC-DS
result     = tpcds_data(scale_factor=1).generate(output_dir=OUT)
csv_result = result.as_csv()
# result.files     → [date_dim.dat, store.dat, item.dat, customer.dat, store_sales.dat]
# csv_result.files → [date_dim.csv, store.csv, item.csv, customer.csv, store_sales.csv]
